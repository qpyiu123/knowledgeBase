## 〇、本周额度使用总说明（2026-11-03 ~ 11-09）

用户要求：**把本周 GPT Plus 额度全部用掉**。原则：

1. 不空转——每个会话/一次性任务必须落下一个**可归档产物**（文档、代码、评测结果、复盘），
   产物缺失视为浪费额度。
2. 额度优先顺序：**设计与评审 > 复现难题 > 写代码 > 数据搬运**。
   模型投入产出最高的场景是"读代码提缺陷"和"新题复现评审"，最低的是大量机械搬运（交给子代理批量做）。
3. 一切改动走既有流程：简报 → 子代理执行 → 我（裁判）独立验收 → 逐文件 commit。
4. 时间预算：本周剩余额度若不足以完成 S1~S5，宁可少批高质量，也不开烂尾批。

## 三、本周批次（S1–S7）——一张表排完

> 执行方式：每批同样"简报 → 子代理/执行器 → 我验收 → commit"。
> 额度多时多批并发，额度少时做好 S1/S2/S4（最高价值）优先。

### S1（设计，额度权重 25%）：方法卡生产协议 v2（Method Card Protocol v2）

**产出**：`docs/METHOD_CARD_PROTOCOL.md`（新文件）。
**内容**（初期即写全，后续迭代加严）：

- 七栏骨架锁定：`title / category / tags / signals / difficulty / source / tools / updated`
  + 正文 `适用场景 → 前置条件 → 步骤 → 脚本 → 失效场景`（Q3-B 已示范）。
- **signals 必须可检索**：不得写只有人能懂的描述；每卡 ≥4 条、≤8 条信号句，
  其中 ≥2 条须来自题目附件或源码的真实片段（防臆造）。
- `source` 指向库内已存在文档（≥1 条），脚本 `--selftest` 必须 exit 0。
- 一卡一脚本或"无脚本速查"二选一；脚本默认参数只读、不联网。
- **每卡必须过浏览器级三查**：front-matter 解析、`meta_text` 出现在索引、
  以卡内 signals 自查检索是否 top10 内。
- 生产方式（防"模型乱写"）：以 backlog 里的 sources 为依据先跑 `kb search`
  收集真实 docs 摘要，再写卡；禁止先写卡后找证据。

**验收**：`docs/METHOD_CARD_PROTOCOL.md` 存在 + 我评审签字 + `pytest` 不减。

### S2（执行，额度权重 25%）：DB-Q4A——20 张方法卡（crypto 11 + web 逐批 9）

- 范围：backlog 前三分之一 —— crypto 11 张（rsa-small-e / rsa-fermat / rsa-coppersmith /
  rsa-dp-leak / rsa-padding-oracle / ecdsa-nonce-reuse / otp-many-time-pad /

**验收（我独立跑）**：
