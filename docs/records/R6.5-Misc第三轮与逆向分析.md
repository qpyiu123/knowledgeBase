# R6.5 第三轮：Misc 试用与逆向检索

## 样本和评法

20 道独立样本，22 份原附件。5 道从旧库官方赛事归档复制，另外 15 道来自 [DownUnderCTF 2022](https://github.com/DownUnderCTF/Challenges_2022_Public)、[DownUnderCTF 2024](https://github.com/DownUnderCTF/Challenges_2024_Public)、[UIUCTF 2023](https://github.com/sigpwny/UIUCTF-2023-Public)、[TJCTF 2023](https://github.com/TJCSec/tjctf-2023-challenges)、[W4terCTF 2023](https://github.com/W4terDr0p/W4terCTF-2023) 的官方仓库。将赛事的取证分类计入本轮 Misc 范围。原件归档在 `work/r65-misc/真题测试集`，按题分目录，详见[清单](../../eval/r65_misc_cases.json)。每题选一个主附件上传，伴随文件用于本机试做。未运行题目程序、ROM 或宏，也未提交 Flag。

流程是看附件报告、查一次资料、从原附件补线索再查、做能回验的检查。用关键词（FTS）和融合两种模式，各看前五条。初跑 80 次；后续核正邮件封数和 USB 抓包格式，并给三题增加同问题、不同分类的对照。最终清单复跑 **86 次**，关键词和融合检索耗时中位数分别为 45.2、80.5 ms。生成模型始终关闭。

## 逆向不用生成模型，先改善什么

用三道已经下载的逆向题，各跑三种输入：普通提问、同一句话只限逆向分类、在同一分类下加实测线索。两种检索共 **18 次**，见[对照清单](../../eval/r65_reverse_observations.json)。

| 样本 | 只限逆向分类 | 加实测线索后 |
| --- | --- | --- |
| UTCTF basic-re | 首条仍是符号执行进阶。 | 给出 x64 ELF、`main/scanf/printf` 后，前五条出现静态定位、汇编和比较逻辑资料。下一步从输入函数的交叉引用追缓冲区和比较点。 |
| ezVM | 首条是 Flutter 或其他逆向赛例；和 jocker 用同一句话时排名完全相同。 | 给出 x64、`check.dll` 的 `calc_run/check` 导出和独立 `data` 后，两种模式都把 VM 指令分派资料排第 1。先查谁读 data、传给哪个函数，再验证是否有取指和分派。 |
| jocker | 和 ezVM 得到相同结果。 | 给出 32 位 PE 的 `VirtualProtect` 导入后，关键词能找到相关 SMC 案例，融合的 VM 资料在第 5。现有资料仍缺“找到调用点 → 核对目标地址和权限 → 找写入该范围的指令”的短步骤。 |

建议先做一个小版本，顺序如下：

1. **附件先给出可查的事实。** 对 PE/ELF 和 ZIP 内的少量二进制成员，先读格式、位数、入口、段权限、导入导出，必要时列少量有偏移的字符串。普通 ZIP 不猜内部程序类型；能读到成员头时再说是 PE、ELF 或其他。附件只读，不自动运行或反编译。
2. **方法卡按当前卡点写。** 一张卡只解决一步，例如“找输入校验”“查 DLL 导出”“确认是否自修改”。列触发线索、第一项操作、要看到的证据、看不到时查哪里。用 Ghidra 或 IDA 的具体入口即可，例如查交叉引用；不需要自动导入整段伪代码。[Ghidra 官方入门](https://ghidra.re/ghidra_docs/GhidraClass/Beginner/Introduction_to_Ghidra_Student_Guide.html)
3. **把推测和事实分开显示。** `VirtualProtect` 是事实，“自修改”还需找到实际写入；EXE、DLL、data 一起给出，先查调用关系，看到取指和分派才走 VM 路线。排序先看结构和符号的明确匹配；没有证据时继续给通用起步，不按文件名猜算法。分类做加权提示，别硬挡跨分类资料：ZFS 原题解和宏资料的对照已经看到这个问题。
4. **验收按下一步能否做成。** 保留三道对照，再选未参与设计的新题。加入正常导入 `VirtualProtect`、但不写代码段的 PE 做反例。看前 3 条有没有正确操作、有没有提前判断成壳或 VM，以及人工找到第一处证据需要几步。先用纯关键词测，再比较 BGE 补充了什么。
