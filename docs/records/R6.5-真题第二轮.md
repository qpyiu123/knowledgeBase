# R6.5 第二轮真题试用

2026-11-06，本机 Windows。以 `2febbae` 为基线，使用便携 Python 和现有 BGE 量化索引（1917 篇、15937 个文本块）。本轮只新增评测清单和记录，未改搜索、附件识别或知识库内容。

## 选题与做法

- 从用户的 `E:/re/` 复制 10 道 Crypto 题，覆盖 RSA 的不同泄漏、曲线参数、格、有限域方程、群、Rabin 和随机数。赛事只在有出处时填写；Factorize 的年份见[赛事主办方回顾](https://offshift.io/blog/2021-02-11-the-offshift-0x41414141-ctf-in-review/)。
- 从 DASCTF 侧栏下载 4 道 Misc、2 道 Reverse。网鼎杯 2020 的 jocker、Teslaaaaa，以及 2021 年的 Firefox Forensics、Nuclear wastewater，有明确赛题出处。平台标它们为“简单”，这次看的是自修改代码、CAN 日志、浏览器密钥库和二维码加内层压缩包等具体步骤。“中等”的菜刀流量和“困难”的 ezVM 用于补充测试，原赛事和年份待核实。下载的“虚幻2”只含一张 PNG，没有纳入本轮。
- 附件统一归入 `work/r65-round2/真题测试集/{crypto,misc,reverse}`。DASCTF 文件按题页 MD5 核对后移入；本地题库原件未改。[固定清单](../../eval/r65_real_cases.json)记录来源、文件校验值、查询和预期帮助。
- 先从题面和附件报告提出问题，再静态查看源码、目录或文件结构，补充题目条件。两种模式各看前五条，打开资料正文判读。首跑 64 次查询；看过结果后，保留原问题，另对 6 题追问，再跑 76 次，原 64 次前五条顺序一致。这里对比的是 API 的关键词检索（FTS）和融合重排（hybrid），不是网页的“语义补充”顺序。
- 试解只使用本地副本。题目脚本和二进制文件只读，不运行；数学试算使用自行编写的代码或仓库已核对的工具。未访问靶机或提交 Flag，生成模型关闭。

## 检索结果

“可用”是前五条里有与本题条件相符、能直接尝试的下一步；“起步”是有相关资料，还要自己补关键条件或转换步骤；“偏题”是两种模式都没有给出合适的下一步。每题取两种模式中较好的结果，以下为补充线索后的人工判读。

| 题目 | 初次 → 追问后 | 返回资料和试做结果 |
| --- | --- | --- |
| PolyRSA | 偏题 → 偏题 | 返回同明文共模、广播或 CRT 故障。实际是两组不同底数；自行交叉升幂消元，求得因子并回验两条泄漏和原密文。 |
| highlow | 可用 | Coppersmith 方法卡第一。可以把保留两端、中间未知的 352 位写成 `p = p0 + 2^400*x`；库中例子只给了连续高位，尚未在本机运行小根求解。 |
| 消逝的曲线 | 偏题 | 命中小阶点等其他 ECC 场景。自行从四点方程做差，消去曲线系数后取 GCD，恢复了 160 位素数和曲线参数，四点均通过回验。 |
| Algebra | 偏题 → 起步 | 首查多为格、LFSR 和门限分享。明确问 Gröbner 基后，关键词模式第一条有 Sage 的 `groebner_basis()` 用例；两组约束仍需分别建模。 |
| Factorize | 可用 | 两种模式第一条都是 Fermat 分解。按资料从向上取整的平方根试起，第一次即得到因子，解出的明文回代通过。 |
| ez_raabin | 起步 | CRT 和 Rabin 有起步资料。试算确认 `hint` 整除 `n`；按 4 的倍数把素数间距从 `2^400` 增加到 `2^400+65536`，未找到因子。下一步应复核公开参数与生成式。 |
| lwe1 | 起步 | 两种模式第一条都是格归约方法卡；需要另补误差区间居中、格基构造与回验。 |
| Subgroup Choreographer | 偏题 | 返回 DH 小子群等资料，缺少从自定义运算表检查阶、逆元和不变量的步骤。 |
| NTRU | 偏题 | 前五条没有稀疏环卷积方法。自行按 4 个非零项枚举位置和符号，得到唯一符合明文系数范围的候选；去掉零填充后格式正确，重算密文一致。 |
| Lunar LCG | 起步 → 可用 | 起初问能否只算低 8 位；核对附件发现模数不是 256 的倍数，且泄漏 6 个完整状态。追问后两种模式都把 LCG 方法卡排第一。复用库中 `recover_a_c`、`predict` 回验 6 个状态，并恢复了符合格式的明文。 |
| 菜刀流量 | 可用 | 附件报告显示未知；文件头资料可识别 PCAPNG，补充协议后两种模式首条均是流量方法卡。静态数到 499 个增强数据包块，其中 8 个包含 HTTP 请求行；还可按会话重组。 |
| ezVM | 起步 | VM 资料说明了指令分派；首条分别偏向 Lua 或 Python 字节码。本机确认主程序和 DLL 均为 x64，DLL 导出 `calc_run`、`check`，可据此追数据读取和调用关系。 |
| jocker | 起步 → 起步 | 融合结果有二进制补丁，追问 SMC（自修改代码）后关键词能找到案例。静态确认是 32 位 PE，导入表确有 `VirtualProtect`；还需查调用点和写入地址。 |
| Teslaaaaa | 起步 → 起步 | 压缩包资料可用于排除加密。内层 ZIP 直接读出 1564 行 CAN 报文，PNG 无 IEND 后附数据；换问 CAN 后，前五条仍未找到报文分组步骤。 |
| Firefox Forensics | 偏题 → 偏题 | 浏览器取证资料以 Chromium 为主。实测 `key4.db` 中有 `metaData`、`nssPrivate`，JSON 有一条加密登录记录；追问后仍缺 NSS（Firefox 使用的加密库）和主密码核对步骤。 |
| Nuclear wastewater | 起步 | 二维码资料提供定位图案和预处理思路。确认外层两个成员可读，内层 `flag.txt` 的加密标志置位；未完成二维码恢复。 |

初次补充线索后：**可用 3、起步 7、偏题 6**。追问后：**可用 4、起步 7、偏题 5**。初次关键词查询耗时中位数 61.9 ms，融合 93.8 ms。只拿附件报告发问时，单 Python 文件的 ZIP 反复搜到二进制补丁、SQL 或 Android 资料；PCAPNG 和二维码有较好的起步资料。未加密 ZIP 仍需要直接给出成员查看方式。

试解中有 **5 道密码题**拿到可本地验证的结果。Factorize 和 Lunar LCG 的关键步骤来自检索；PolyRSA、消逝的曲线和 NTRU 由试用者自行推导。这个区别比单看“有没有解出来”更能指出该补什么资料。

## 先修什么

1. **从附件开始。** 给普通 ZIP 的成员查看、PCAPNG 识别和 PE 导入表起步提示，让用户少走一次泛搜。
