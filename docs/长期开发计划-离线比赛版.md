## 1. 用户已经确定的方向

1. 最终开发成果保存在移动硬盘的接续项目，便于分发和换机使用。
2. 首要用途是查语言与库文档、CTF 技巧、题型和参考代码；根据题目信息找到相关方法和下一步检查。

## 4. 结构和实现约定

继续使用标准库 Python HTTP 服务、SQLite、React + TypeScript + Mantine。优先复用现有检索、阅读、工作区组件，不引入新的常驻数据库或代理框架。

资料分为精选速查与完整原文两个入口：精选内容帮助定位，原文保留细节。资料类型、整理状态和复现状态分别标记。代码保存依赖、输入输出、版本与案例常量；同源副本合并展示。

主要模块：

1. 资料读取与比赛前索引构建。
2. 符号、错误字符串、关键词和代码检索。
3. 可选语义检索及来源去重。
4. 条件与相关案例提示。
5. 当前题目事实、假设、待查项和尝试记录。
6. 按需解释及旧模型服务适配。
7. 离线启动、备份恢复与分发。

查询只读已经构建好的索引，不在用户搜索时重算全库。资料更新与个人题目记录更新分别处理。切换编码器时重建相应向量索引，保留原索引供比较。

## 6. 实验与测试怎样开展

保留三个独立试验：A 文档代码快查、B 条件关联、C 当前卡点检索。先比较 A 与 A+B，再决定 C 的实现范围。每次记录问题、改动、固定样本、结果和去留，不把所有试验同时合进默认功能。

先固定约 30 个问题，覆盖语言/API、错误排查、模糊题面、前提差异、当前卡点与资料缺失。人工复核应命中的资料和关键条件，再用于比较。原 22 条评价草稿继续用于开发检查，不混充新评测。

比较先固定相同语料，再逐项增加检索方式。记录第一屏时间、找到可用文档/代码的时间与点击次数、无关建议、条件遗漏和内存峰值。冷启动与重复查询分别记；用户常用工具和虚拟机开启后的结果另记。

自动化测试默认使用离线样例和模型 Mock，不启动真实模型或执行未知附件。真实模型、核显和整包断网验收作为独立步骤记录。

## 7. 每个版本的工作顺序

1. 阅读规则、项目记忆、当前批次；检查 Git 状态和已有变更。
2. 写本批目标、具体文件、验收问题和不做项；重要设计不确定时询问用户。
3. 先完成一个可用的小部分，运行对应测试，再扩到本批其余内容。
4. 完成回归、构建和必要的浏览器检查；记录命令、结果和失败原因。
5. 更新 PROJECT_MEMORY、DEVELOPMENT_PLAN、探索记录与版本记录，下一步具体到可执行任务。
6. 检查 Git 差异和暂存清单，仅提交本批已验收文件。提交后给出 hash、功能、测试及下一批事项。

完成一个版本后默认继续下一批。权限、关键设计冲突或缺少必要输入时先记录问题并询问用户，不反复重试同一失败任务。不要按历史文档主动消耗额度或派发批量代理。
