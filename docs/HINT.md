# 没思路时怎么用

针对「题面全是废话、附件看不出门道」的场景。

## 一条命令

```powershell
kb hint <附件路径> -q "题面原文"
```

不给路径就自动扫 `work/attachments/`：

```powershell
kb hint
```

## 它做了什么

```
1. 侦察附件        recon.probe_file
   ├─ 按魔数判真实类型（不信扩展名）
   ├─ 雕刻内嵌文件（PNG/JPG/ZIP/GZIP/PDF...）
   ├─ 提取关键词优先的可读字符串
   ├─ 自动解码 base64/hex（解好直接给你）
   └─ 按格式做结构分析（PNG chunk / ZIP 目录 / WAV 头）

2. 检索知识库
   └─ 只用侦察事实做 query（题面不参与，避免噪声）

3. 小模型推方向    本地模型（按 config.toml 解析）
   └─ 输入侦察事实，输出 3 个方向 + 依据 + 具体做法
```

## 输出长什么样

```
== work/attachments/mixed.bin ==
模型 qwen2.5-coder-7b:local（按 config.toml 解析）

建议的探索方向：

  1. 提取并解压 ZIP 内嵌文件（偏移 0xf6）
     依据: 0xf6 偏移处为 ZIP (138 字节)，ZIP 格式可包含可读文本或 flag
     做法: 使用 extract_embedded 提取偏移 0xf6 处的 ZIP，然后 unzip 解压

  2. 提取并解压 GZIP 内嵌文件（偏移 0x1bc）
     依据: 0x1bc 偏移处为 GZIP (41 字节)，常用于压缩文本

  3. 检查内嵌 JPEG 是否含隐写

知识库相关条目：
  - 文件雕刻与恢复（foremost / binwalk / photorec）
```

## 关键设计：不让模型凭空想

这是整个功能能用的前提。

**失败的架构**（试过）：

```
选手观察 → 模型直接想候选 → 大量错误
```

旧记录称 7B 把「共模攻击」当成要排除的选项，4B 选了「中国剩余定理」。本批未复现。
两个模型都没有足够细的 CTF 技法储备。

**现在用的架构**：

```
侦察工具 → 硬事实（偏移/类型/字符串/解码结果）
   ↓
模型只负责：根据这些事实，哪个最可能出 flag
```

模型不需要"知道"技法存在，只需判断给定线索的价值。这个任务 4B 够用。

## 踩过的坑

### 假线索比没线索更糟

早期版本会自动尝试解码所有看起来像 base64 的串：

```
JUNKJUNKJUNK...  --base64-->  %CJ%CJ%CJ%CJ...
```

`JUNKJUNK` 全在 base64 字母表里，解码出控制字符乱码，但旧逻辑只检查
"是否可打印"就放行了。

**后果**：模型信了这个假线索，把三个方向全用在解乱码上，
完全忽略了旁边真正的 ZIP 和 GZIP。

修复：解码结果必须同时满足
- 无控制字符
- 可读字符占比 ≥ 90%
- 不含大段重复模式
- 解出内容至少含 3 个字母或中文

### 题面不能参与检索

把「各位选手好，这是综合题」放进检索 query，会命中
「硬件 CTF 方法论」和「Docker for Everyone Plus」。

现在只用侦察事实构造 query。

### PNG 会检索出 JPG 条目

向量模型对 PNG/JPG 区分不好。加了个硬约束：
附件是 PNG 时，标题只提 JPG 的条目降权。

## 局限

1. **只覆盖文件类题目**。纯 Web、纯交互式题目没有附件可侦察，用不上。

2. **方向是"下一步做什么"，不是完整解法**。它告诉你先去试 ZIP，
   但解出来怎么办还得自己看。

3. **深度隐写仍需专业工具**。LSB 位平面、DCT 系数、频谱图这些，
   侦察工具看不出，需要 zsteg / steghide / Audacity（本机未装）。

4. **加密压缩包需要密码**。工具会报告"有密码"，但不会爆破。
